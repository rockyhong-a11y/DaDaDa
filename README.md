# DaDaDa · 서울 스카이 스윙

실제 서울 좌표 위에 세운 빌딩숲을 **웹스윙으로 건너는 3D 리듬 게임**. 브라우저에서 바로 돌아가는 웹앱이며,
설치·서버·외부 에셋 없이 정적 파일만으로 동작한다.

BGM 의 박자에 맞춰 웹을 쏘면 고도를 유지하며 다음 건물로 넘어가고, 박자를 놓치면 고도가 꺼져 추락한다.
스테이지마다 서울의 실제 지역을 하나씩 가로지르고, 마지막에는 그 동네의 랜드마크 정상까지 타고 오른다.

## 실행

### 1. 웹에서 바로 — GitHub Pages

**https://rockyhong-a11y.github.io/DaDaDa/** — PC · 모바일 브라우저 모두 지원한다.

저장소 **Settings → Pages** 의 소스 설정에 따라 아래 셋 다 동작한다.

| Pages 소스 | 서빙되는 것 | 비고 |
|-----------|-----------|------|
| **Deploy from a branch → `/docs`** (권장) | `docs/index.html` + `docs/audio/` | CI 불필요. 커밋된 파일이 곧바로 루트 URL 이 된다. |
| Deploy from a branch → `/` (root) | 루트 `index.html` → `./docs/` | 한 번 넘어가므로 주소가 `/DaDaDa/docs/` 가 된다. |
| GitHub Actions | `dist/` | `.github/workflows/pages.yml` 의 push 트리거 주석을 풀어야 자동 배포된다. |

> 브랜치 배포와 Actions 배포가 **동시에** 켜져 있으면 push 마다 배포가 두 번 일어나
> 어느 쪽이 최종본인지 정해지지 않는다. 그래서 워크플로는 기본이 수동 실행이고,
> 브랜치 배포 하나만 자동으로 돌게 해 뒀다.

### 2. 그냥 열기 — 단일 HTML 파일

**`docs/index.html`** 을 브라우저로 열면 끝이다. 서버도 설치도 필요 없다.
JS·CSS·아이콘까지 전부 한 파일(약 1.2MB) 안에 들어 있어 USB 에 담아 다녀도 그대로 돌아간다.

실제 음원 BGM 을 쓰는 스테이지만 옆자리 `docs/audio/` 를 함께 받아 간다. 음원을 못 받아오는
환경(파일 하나만 떼어 간 경우, `file://` 로 연 경우)에서는 **신스 BGM 으로 자동 폴백**하므로
게임은 어디서든 그대로 굴러간다. `dist-single/dadada.html` 은 아예 음원을 담지 않는
"파일 하나" 배포본이다.

### 3. 소스로 개발하기

```bash
npm install
npm run dev            # http://localhost:5173
npm run build          # dist/ + dist-single/dadada.html + docs/index.html
npm run build:single   # 단일 파일만
npm run build:pages    # 단일 파일 + docs/ 갱신
npm run preview        # 빌드 결과 확인
```

> **루트의 `index.html` 은 개발 서버용 진입점이다.** 브라우저로 직접 열면 실행되지 않는다
> (`file://` 에서는 origin 이 `null` 이라 모듈 스크립트·스타일시트가 CORS 로 차단된다).
> 직접 열면 흰 화면 대신 안내 문구가 뜨고, http(s) 로 서빙 중이라면 `./docs/` 로 자동 이동한다.
>
> 같은 이유로 `dist/index.html` 도 직접 열면 안 되고 정적 서버로 서빙해야 한다.
> 단일 파일 빌드는 번들을 IIFE 로 뽑아 일반 `<script>` 로 인라인하기 때문에 이 제약이 없다.

## 조작

| 입력 | 동작 |
|------|------|
| `Space` `J` `K` `F` `D` `↑` / **화면 아무 곳이나 탭** | 웹 발사 · 공중 트릭 |
| `Esc` | 일시정지 |

모바일은 세로·가로 모두 플레이할 수 있고, 가로가 시야가 넓다.
노치·홈 인디케이터 영역을 피해 HUD 를 배치했고, 주소창이 접히고 펴져도 캔버스가 따라 붙는다.

타이밍은 화면 정중앙의 **리티클**(고리 모양 기준선)이 담당한다. 다가오는 노트는 화면
가장자리가 아니라 정중앙에서, 실제 판정 크기보다 훨씬 큰 링으로 나타나 그 자리에서 그대로
오므라들며 기준 링 크기에 딱 맞아떨어지는 순간이 판정 시점이다 — 리듬 게임의 "어프로치
서클" 방식이다. 테두리만 있는 링이라 배경(건물·플레이어)을 가리지 않고, 여러 노트가 겹쳐도
서로 다른 색·모양이라 구분이 된다. 예전에는 3D 공간 속 앵커 지점에 별도의 예고 링을
띄웠는데, 그 링이 웹 로프와 같은 자리에 겹쳐 오히려 잘 안 보인다는 문제가 있어서 걷어내고
이 방식으로 통합했다. 웹 로프 자체도 반투명하게 낮춰 뒤가 비쳐 보이게 했다.

- **◆ 스윙 노트(청록 마름모)** — 새 웹을 쏴 다음 건물로 넘어간다. 탭한 자리에 흰빛이 확 터졌다가
  색이 번지며 잦아드는 2단 파티클 팝 이펙트가 뜬다.
- **● 에어 노트(분홍 원)** — 스윙 도중 넣는 공중 트릭. 점수와 모멘텀이 오른다.
- 판정은 `PERFECT / GREAT / GOOD / MISS`. 미스가 쌓이면 고도가 꺼지고, 스윙을 연달아
  놓치면 추락해 실패한다.
- **GLIDE · 활강 구간** — 스테이지마다 **중간과 마지막에 하나씩**, 웹을 놓고 도시 위로 솟아올라
  서울 전경을 내려다보며 활공하는 구간이 들어간다. 중간 활강은 경로 한복판에서 주변 스카이라인보다
  210~260m 위까지 부풀어 올랐다 내려오고, 마무리 활강은 피날레 타워 정상에서 몸을 던져 도시 위를
  길게 미끄러지며 곡을 닫는다. 활강 중에는 걸 웹이 없으므로 그 구간의 스윙 노트는 전부 공중 트릭으로
  바뀌고(진입 도약 한 번만 스윙으로 남는다), 카메라가 뒤·위로 빠지며 시야각이 넓어져 발밑으로 도시가
  펼쳐진다.
- **SWING POWER · 피버 모드** — 게이지는 0%에서 시작해 노트를 성공시킬 때마다 차오른다
  (PERFECT 가 가장 많이, 미스는 깎는다). 100%를 채우면 **피버 모드**가 8초간 발동하고,
  그동안은 타이밍을 볼 것 없이 **연타만으로** 눈앞의 노트가 전부 PERFECT 로 밀려 나간다.
  피버 중에는 게이지가 남은 시간에 맞춰 줄어들고, 끝나면 0%부터 다시 쌓는다.
  즉 이 게이지는 체력이 아니라 "모아서 터뜨리는" 보상 자원이다.
- **노트는 순수 터치(탭)만 쓴다** — 홀드·연타 같은 별도 입력 방식은 없다. 대신 노트가
  얼마나 빨리 몰아치는지(스테이지 템포)에 맞춰 리티클의 등장 시간을 스테이지마다 다르게
  잡는다: 느린 스테이지는 넉넉하게 미리 보이고, 고 BPM·촘촘한 스텝을 쓰는 빠른 스테이지는
  접근 링이 짧게, 덜 겹치게 등장한다 — 화면에 동시에 떠 있는 링 개수가 스테이지 속도와
  무관하게 비슷하게 유지된다. 리듬 패턴도 실제 노트 도착 간격이 너무 좁게 연속되면 몇 개씩
  솎아내 숨 돌릴 틈을 준다(스윙 노트는 경로 이동의 핵심이라 절대 솎아내지 않는다).
- **판정 연출(태고의 달인 스타일)** — 리티클의 기준 링이 판정 색으로 확 번쩍이며 커졌다
  가라앉고, 판정이 난 노트 링도 잠깐 그 색으로 물들었다 사라진다. 10콤보마다 콤보 숫자가
  한 번 크게 튀며 금색으로 번쩍이는 마일스톤 연출도 있다.
  판정 **텍스트**는 상단 HUD 와 리티클 사이 빈 띠에 띄운다 — 예전엔 리티클 위에 겹쳐
  띄웠는데 접근 링이 최대 지름 220px 까지 커지는 탓에 정작 쳐야 할 노트를 글자가 가렸다.
  PC·모바일 세로·모바일 가로 세 레이아웃 모두에서 링이 차지하는 세로 범위를 침범하지
  않도록 위치와 글자 크기를 따로 잡아 두었다.

싱크가 밀리면 **설정 → 오디오 오프셋**으로 보정한다.

### 인게임 위치 표시

날아가는 곳이 실제로 어디인지 게임 안에서 바로 보여 준다.

- **현재 위치 태그** — 화면 좌상단 스테이지 이름 아래에, 지금 지나는 아파트 단지·상권·구역
  이름이 뜬다(예: `목동 3단지`, `여의도 증권가 북측`). `City.zoneAt()` 이 플레이어 좌표가
  어느 명명된 블록 안에 있는지 매 프레임 판정해 갱신한다.
- **랜드마크 이름표** — 시야에 들어온 랜드마크는 **한 번에 하나씩이 아니라 전부 동시에**,
  각자의 건물 옥상 위 화면 좌표에 이름표로 붙는다. 거리에 따라 크기·투명도·블러가 달라져
  **스카이라인 저 끝의 이름은 흐릿하게 겨우 보이다가 다가올수록 커지고 또렷해진다.**
  표시 반경도 건물 높이에 비례해 커서 555m 롯데월드타워 같은 초고층은 1km 밖에서도 뜬다.
  상단 HUD·하단 진행바와 겹치는 세로 범위로 들어온 이름표는 자동으로 숨긴다.
- **이름표가 붙는 건물 수(실존 랜드마크의 약 5.7배)** — 손으로 좌표를 적어 둔 실존 랜드마크는
  5개 스테이지 합쳐 70채뿐이라 이름표가 드문드문 떴다. 그래서 이름 붙은 블록(아파트 단지·
  상권 등)마다 그 안에서 가장 높은 4채에 블록 이름을 물려준다 — 아파트 단지는 실제 관례대로
  `목동 3단지 101동`, 그 외는 `오목교 주상복합 A동` 식이다. 총 70채 → **401채**.
  실존 랜드마크(금색)와 물려받은 동(회색)은 색으로 구분되고, `kind` 는 건드리지 않아
  도시 렌더링(색·형상 분류)은 그대로다 — 붙이는 건 이름표뿐이다.
- **구역 배너** — 이름 붙은 블록(스테이지당 17~22개)에 처음 들어올 때 화면 아래쪽에
  청록색 카드가 한 번씩 뜬다.

## 서울 지도 데이터

### 좌표계

모든 지오메트리는 실제 위경도에서 출발한다. `src/world/geo.ts` 의 `GeoProjector` 가
스테이지 원점을 기준으로 위경도를 로컬 ENU 미터 좌표로 옮긴다
(`+X` 동, `+Y` 위, `−Z` 북). 도시 규모에서 등거리 원통 근사의 오차는 0.1% 미만이다.

### 스테이지 데이터 (`src/data/stages/`)

각 스테이지는 세 층으로 기술한다.

1. **경로(route)** — 실제 도로를 따라가는 위경도 웨이포인트.
   테헤란로는 방위각 69도로 강남역(37.4979, 127.0276)에서 삼성역(37.5088, 127.0631)까지 이어진다.
2. **랜드마크(landmarks)** — 실존 건물의 좌표·평면 크기·높이·층수.
   롯데월드타워 555m/123층, 파크원 타워1 333m/69층, 63스퀘어 250m/60층,
   트레이드타워 228m/54층, N서울타워 237m(해발 480m) 등. 높이는 공개된 실측값의 근사치다.
3. **블록(blocks)** — 도시 블록의 중심 좌표·크기·방위각과 용도(판상형 아파트, 타워형 아파트,
   고층 업무, 저층 상가, 재래시장, 공원, 수면 …). 생성기가 용도별 형태 규칙으로 건물을 채운다.
   목동 신시가지는 남향 판상형이 85~95m 간격으로, 테헤란로는 200×140m 블록이 도로 양쪽에 반복된다.

여기에 **지형(terrain)** 이 더해진다. 남산은 반경 900m·정상 243m 의 구릉으로 모델링되어
건물 지반고와 비행 고도에 실제로 영향을 준다 — 스테이지 5 후반은 산을 타고 오르는 구간이다.

경로 주변은 손으로 기술한 블록이, 그 바깥은 저주파 노이즈 기반 배경 시가지가 채워
지평선까지 빌딩숲이 이어진다. 스테이지당 약 7,500~10,500동이 생성되며 형태별 인스턴싱으로
드로우콜 몇 개에 처리된다.

### 실측 건물 데이터 (선택)

`npm run fetch:osm` 을 돌리면 OpenStreetMap Overpass API 에서 각 스테이지 영역의
**실제 건물 윤곽과 층수**를 받아, 폴리곤을 최소 면적 회전 사각형으로 근사해
`src/data/osm/*.json` 으로 굽는다. 데이터가 있으면 도시 생성기가 블록 규칙 대신 이 실측
발자국을 쓴다(`src/world/citygen.ts` 의 `placeOsmFootprints`). 랜드마크·지형·수면은 그대로 유지된다.

```bash
npm run fetch:osm            # 5개 스테이지 전부
npm run fetch:osm -- jamsil  # 특정 스테이지만
```

> 데이터를 굽지 않아도 게임은 그대로 돌아간다. 이 저장소에는 OSM 스냅샷을 커밋하지 않았다
> (라이선스 표기 부담과 용량 때문이며, 개발 환경의 네트워크 정책상 Overpass 접근이 막혀 있어
> 실제 응답으로 검증하지는 못했다). 사용 시 OpenStreetMap contributors / ODbL 1.0 표기가 필요하다.

### Google 실사 3D 타일 (선택 · 실험적)

**설정 → Google 3D Tiles API 키**에 본인 키를 넣고 "실사 3D 타일 배경 사용"을 켜면
Google Photorealistic 3D Tiles 를 게임 좌표계에 정합해 배경으로 띄운다
(`src/world/tiles3d.ts`). ECEF → 스테이지 원점 ENU → three.js Y-up 으로 변환한 행렬을
타일 그룹에 직접 물린다. 키는 브라우저 `localStorage` 에만 저장되고 어디로도 전송되지 않는다.

> 게임의 앵커·비행 고도는 자체 도시 모델에서 계산하므로 실사 타일과 완벽히 일치하지는 않는다.
> 배경 레이어로만 쓰는 실험 기능이며, 키가 없으면 모듈 자체가 로드되지 않는다.
> API 키가 없어 실제 타일 응답으로는 검증하지 못했다.

## 리듬 · 음악

BGM 은 두 갈래다. 기본은 **Web Audio 실시간 합성**(`src/audio/music.ts`)이고, 스테이지가
`bgm` 을 지정하면 **실제 음원 파일**(`src/audio/track.ts`)을 대신 재생한다. 어느 쪽이든
노트 차트와 같은 시계(`conductor.ts`)를 쓰므로 음악과 노트는 구조적으로 어긋날 수 없다.

- `conductor.ts` — 마스터 클럭. 모든 시간은 `AudioContext.currentTime` 기준이라
  프레임 드랍이나 탭 전환에도 판정이 밀리지 않는다.
- `track.ts` — 실제 음원 재생기. `Conductor.toAudioTime()` 이 곡 기준 시간을
  AudioContext 절대 시각으로 바꿔 주고 `AudioBufferSourceNode.start(when, offset)` 이
  거기에 샘플 단위로 붙는다. 재생을 걸 때마다 "지금 곡 시간"을 그대로 offset 에 넣으므로
  **일시정지 후 재개해도 앞이 잘릴 뿐 싱크는 항상 맞는다.**
  받아오지 못하면 조용히 신스 BGM 으로 되돌아간다.

> **음원은 판을 열기 전에 다 받는다.** 3MB 짜리 파일을 백그라운드로 받으면서 판을
> 시작하면, 회선이 느릴수록 앞부분이 통째로 무음이 되고 곡이 중간부터 튀어 들어온다
> (1.5Mbps 로 재현해 보면 18초가 무음이었다). 리듬 게임에서 이건 "BGM 이 안 바뀌었다"
> 로 보이는 실패다. 그래서 로딩 화면이 실제 진행률(`BGM 내려받는 중… 63%`)을 띄우며
> 기다린 뒤에 판이 열린다. 15초 안에 못 받으면 기다리기를 포기하고 신스로 넘어간다.
> 지금 어느 쪽으로 돌고 있는지는 `?debug=1` 오버레이의 `bgm track` / `bgm synth` 와
> 콘솔 한 줄로 확인할 수 있다.

- `voices.ts` — 킥·스네어·클랩·하이햇·베이스·서브베이스·리즈·플럭·리드·패드·스탭·크래시·
  라이드·스윕·**보컬**을 절차적으로 합성.
- `music.ts` — 16분음표 단위 룩어헤드 시퀀서. 예전에는 16마디를 곡 끝까지 그대로 반복했지만,
  지금은 곡 전체 길이에 비례해 **인트로 → 벌스 → 빌드업 → 코러스(드롭) → 브레이크다운 벌스 →
  빌드업 → 파이널 코러스**로 이어지는 아케인지먼트를 짠다. 벌스와 코러스는 서로 다른 코드
  진행을 쓰고, 코러스에서만 리드 멜로디(스타일별로 손으로 쓴 훅 두 개를 번갈아 씀)·서브베이스·
  라이드 심벌이 들어오며, 섹션이 바뀌는 순간 크래시 심벌이 한 번 터진다. 스타일 프리셋
  (선셋팝 / 신스웨이브 / K-POP / 드럼앤베이스 / 하드코어)마다 BPM·드럼 패턴·코드·리드 훅이 다르다.
- `sfx.ts` — 판정음은 정확도에 따라 음정이 달라지고, PERFECT 콤보가 쌓이면 음이 올라간다.

### 보컬 (포먼트 합성)

**녹음된 목소리가 아니라, 목소리가 만들어지는 방식 자체를 합성한다.** 신스 BGM 에는
보컬 샘플을 쓸 수 없으므로(파일 하나로 굴러가야 하고, 라이선스 붙은 음원을 넣을 수도 없다)
사람의 발성 구조를 그대로 모델링했다. 실제 음원을 지정하지 않은 스테이지와, 음원을
못 받아온 모든 상황에서 이 목소리가 노래한다.

```
성대(톱니 + 사각파)  →  성도 공명(모음별 포먼트 3개 병렬 밴드패스)  →  숨소리(대역 노이즈)
                     ↑
                   비브라토(5.4Hz)
```

모음마다 실제 발성의 F1/F2/F3 측정값을 넣어 두어(`FORMANTS`), 같은 음정이라도 아·에·이·오·우가
뚜렷이 구분돼 들린다. 자음까지는 합성하지 않으므로 가사가 또렷하진 않지만, "사람이 부르는
훅 라인"으로는 확실히 읽힌다 — 실제 노래의 `아—아— 오오—` 같은 코러스에 해당한다.

> **포먼트 게인 보정.** 톱니파 배음은 `1/n` 로 줄어들기 때문에 포먼트 표의 게인을 그대로 쓰면
> F2·F3 가 F1 에 묻혀 '이'와 '오'가 거의 같은 소리로 들린다. 그래서 포먼트 주파수에 비례해
> 게인을 올려 배음 감쇠를 상쇄한다. 오프라인 렌더 후 대역 에너지를 재 보니 모음 간
> 스펙트럼 거리가 **0.036 → 0.114 로 3배** 벌어졌고, 대역 분포도 교과서적인 모음 모양이 됐다
> (`이`=고역 93%, `에`=중역 60%, `오`·`우`=저역 우세).

- 코러스에서는 **합창 훅**(원음 + 옥타브 + 5도, 3겹)이 메인 멜로디를 부르고, 리드 신스는
  뒤로 물러나 목소리를 앞세운다.
- 벌스에서는 낮고 옅은 **한 줄짜리 보컬 라인**이 흐른다.
- 스타일 프리셋 5종 모두 각자의 보컬 훅을 갖는다 — 선셋팝은 훅이 곡의 주인공이라 리드 신스가
  뒤로 물러나고, K-POP 은 짧고 또렷하게 끊어 치고, 하드코어는 내지르는 식이다.

### 실제 음원에 차트 붙이기 (STAGE 1 · 목동)

목동만 실제 음원(`docs/audio/mokdong.mp3`, 140.01초)을 쓴다. 음원에는 BPM 이 적혀 있지 않으므로
파형에서 직접 뽑았다 — 스펙트럼 플럭스로 온셋 엔벨로프를 만들고(FFT 1024 / hop 128, 저역 킥 대역에
1.6배 가중), 70~180BPM 을 0.05 간격으로 훑으며 **최적 위상에서의 빗살 필터 응답**을 재는 방식이다.

| 후보 | 돌출도 |
|---|---|
| **98.00 BPM** | **2.79** |
| 78.4 | 2.13 |
| 130.65 | 1.98 |

98.00 에서 응답이 뾰족하게 서고(±0.01 만 벗어나도 2.73 → 2.60 으로 떨어진다) 나머지 후보는 전부
98 의 유리수배였다. 마디 머리는 저역 킥 에너지가 가장 센 박으로 잡아 **0.889초**로 확정했다.

곡이 붙으면 차트와의 관계가 뒤집힌다. 신스 BGM 은 차트가 원하는 만큼 늘어나 주지만, 음원은
길이가 고정이라 **곡이 끝나기 전에 정상에 도착해야 한다.** 그래서 음원 스테이지는 곡 길이를
스윙 예산으로 환산해서, 모자라면 경로 스윙을 줄여 같은 거리를 더 빨리 날고, 남으면 마무리
활강을 늘려 곡의 클라이맥스 위에서 도시를 길게 내려다본다 — 경로 스윙을 늘리는 쪽은 비행
속도를 떨어뜨려 스테이지 체감이 통째로 느려지므로 쓰지 않는다. 목동은 예산이 남아 마무리
활강이 6 → 12 스윙(14.7초)으로 늘었고, 차트는 132.2초에 끝나 137초 예산 안에 들어간다.

노트 차트는 `src/game/chart.ts` 가 지형에서 생성한다.

```
리듬 패턴 → 스윙 구간 분할 → 활강 구간 배치 → 앵커 옥상 선택 → 비행 고도 결정 → 건물 관통 회피 → 노트 밀도 조정
```

- 스윙 주기(기본 2박)마다 새 웹을 쏘고, 그 사이 노트는 공중 트릭(에어 노트)이 된다.
  덕분에 16비트 밀도를 유지하면서도 스윙 간격은 20~35m 로 자연스럽게 유지된다.
- **좌우로 오가는 비행 라인** — 착지점을 경로 중심선 위에 그대로 두면 앵커만 좌우로 살짝
  바뀔 뿐 몸은 정면으로만 나아가 밋밋하다. 그래서 착지 노드 자체를 중심선 좌우로 번갈아
  (도약 거리의 52%, 최대 82m) 밀어 두고, 앵커는 그 스윙이 향하는 쪽 바깥에 건다. 매 스윙이
  왼쪽 끝 → 오른쪽 끝을 가로지르며 감아 돌게 되어 실제 이동 거리도 40% 늘었다.
- **이음매 없는 곡선(`swingPointSmooth`)** — 구간마다 독립적으로 구면 보간하면 위치는 이어져도
  **속도 방향이 노드마다 꺾여서** 한 칸씩 끊어 가는 느낌이 난다. 그래서 노드 근처에서는 이웃 구간의
  궤적을 `t<0` / `t>1` 로 외삽해 겹쳐 섞는다 — 두 궤적 모두 그 노드를 정확히 지나므로 위치는
  그대로고 접선만 평균 나 코너가 사라진다. 구간 내 이징도 옅게(0.28 → 0.1) 줄여 스파이더맨처럼
  좌우로 계속 흘러가는 곡선이 된다. 판정은 곡 시간축의 노트가 맡고 이 곡선은 "몸이 어디 있는가"만
  그리므로, 이음매가 뭉개져도 타이밍에는 영향이 없다.
- 앵커는 목표 고도에 가장 어울리는 옥상을 고르고, 필요한 높이만큼 옥상 철탑을 세운다
  (실제 서울 옥상의 통신 철탑·광고탑처럼 보이도록 항공장애표시등을 얹었다).
- 궤적은 앵커를 중심으로 시작점과 끝점을 구면 보간한 진자 곡선이다. 줄 길이를 함께 보간해
  웹을 감았다 푸는 느낌을 낸다.
- 마지막으로 궤적을 샘플링해 건물을 뚫는 지점이 있으면 고도를 밀어 올린다.
  현재 5개 스테이지 전부 **관통 0**.
- **터치 노트 밀도 밸런싱** — 리듬 패턴만 그대로 채우면 고 BPM·촘촘한 스텝(0.5박)을 쓰는
  고난도 스테이지에서는 숨 돌릴 틈 없이 노트가 몰아칠 수 있다. 최소 간격(난이도가 높을수록
  더 좁게 허용)보다 좁게 몰린 에어 노트가 일정 개수 이상 연속되면 하나씩 솎아내 리듬 골격은
  유지하되 손이 쉴 틈을 준다. 스윙 노트는 경로 이동의 핵심이라 절대 솎아내지 않는다.

검증용 스크립트가 함께 있다.

```bash
./scripts/run-dev.sh src/dev/citycheck.ts    # 스테이지별 건물 수·높이 분포
./scripts/run-dev.sh src/dev/chartcheck.ts   # 노트 수(스윙/에어)·속도·고도·관통 검사
./scripts/run-dev.sh src/dev/zonecheck.ts    # 경로상에서 뜨는 구역·랜드마크 이름 미리보기
```

## 렌더링

- **three.js r185**, WebGL2. 후처리는 `UnrealBloomPass` + `OutputPass`(ACES 톤매핑).
- 건물은 형태별 `InstancedMesh` 로 묶고, 커스텀 GLSL 로 창문 격자를 절차적으로 그린다
  (`src/world/buildingShader.ts`). 용도마다 창 간격이 다르고, 켜진 창의 비율·밝기·색온도
  (백색·전구색·형광색)가 흩어지며, 저층부는 상가라 항상 밝다.
- 창문 격자는 **거리가 아니라 픽셀당 격자 수**(`fwidth`)로 디테일을 끈다. 원경에서 격자가
  지글거리지 않고 건물 전체가 은은하게 빛나는 덩어리로 자연스럽게 수렴한다.
- 90m 넘는 건물 옥상에는 항공장애표시등이 각자 다른 주기로 깜빡인다.
- 시간대 프리셋(노을 / 땅거미 / 밤 / 새벽)마다 하늘 그라디언트·태양 방향·안개·창문 점등률·
  블룸 세기가 통째로 바뀐다.
- 한강·석촌호수는 잔물결과 도시 불빛 반사를, 지면은 도로 격자와 가로등을 셰이더로 그린다.

## 모바일 대응

- **입력** — 화면 아무 곳이나 탭하면 웹이 나간다. 포인터 리스너를 캔버스가 아니라 `window`
  에 붙였다. HUD 오버레이가 화면 전체를 덮고 있어 캔버스에만 붙이면 터치가 닿지 않는다.
- **오디오** — 첫 제스처에서 `AudioContext` 를 깨우고 무음 버퍼를 한 번 흘려보내
  iOS Safari 의 오디오 잠금을 푼다.
- **화질** — 첫 실행 시 포인터 종류·코어 수·메모리·화면 크기로 화질을 정하고
  (`detectQuality`), 총 픽셀 수 예산을 둬 고DPR 폰에서 셰이딩이 폭주하지 않게 한다.
  플레이 중 프레임이 계속 모자라면 한 단계 자동으로 낮춘다(설정에서 직접 고르면 자동 조정 해제).
- **레이아웃** — `100dvh` 와 `env(safe-area-inset-*)` 로 주소창·노치를 피하고,
  세로 높이가 좁은 가로 모드에서는 HUD 를 압축한다. 캔버스 크기는 `window.innerHeight` 가
  아니라 캔버스의 실제 CSS 크기에서 읽는다.

## 단일 파일 빌드

`vite.single.config.ts` 의 `inlineEverything` 플러그인이 산출물을 HTML 하나로 합친다.

- `rollupOptions.output.format: 'iife'` + `inlineDynamicImports: true` — 코드 분할을 없애
  동적 import 까지 한 번들로 합친다. 모듈이 아닌 일반 스크립트라 `file://` 에서 CORS 에 걸리지 않는다.
- `assetsInlineLimit: MAX_SAFE_INTEGER`, `cssCodeSplit: false` — 에셋과 CSS 를 전부 인라인.
- 인라인할 때 `String.replace` 의 **치환 문자열 대신 함수**를 쓴다. 문자열을 쓰면 번들 코드
  안의 `$&` `$1` 같은 시퀀스를 replace 가 치환 패턴으로 해석해 JS 가 조용히 깨진다.
- 코드·CSS 안의 `</script` `</style` 는 이스케이프해 태그가 조기 종료되지 않게 한다.

## 개발용 URL 파라미터

| 파라미터 | 동작 |
|----------|------|
| `?stage=<id>` | 타이틀을 건너뛰고 바로 시작 (`mokdong` `yeouido` `jamsil` `teheran` `cbd`) |
| `?auto=1` | 자동 플레이 (데모·검증용) |
| `?debug=1` | FPS · 카메라 거리 · 고도 표시 |

예: `http://localhost:5173/?stage=jamsil&auto=1&debug=1`

## 설정

음악/효과음 볼륨, 오디오 오프셋(±150ms), 그래픽 품질(낮음은 블룸을 끄고 해상도를 제한),
Google 3D Tiles 키. 기록과 설정은 `localStorage` 에 저장되며, 저장이 막힌 환경에서도
게임은 그대로 돌아간다.
