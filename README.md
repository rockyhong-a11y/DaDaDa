# DaDaDa · 서울 스카이 스윙

실제 서울 좌표 위에 세운 빌딩숲을 **웹스윙으로 건너는 3D 리듬 게임**. 브라우저에서 바로 돌아가는 웹앱이며,
설치·서버·외부 에셋 없이 정적 파일만으로 동작한다.

BGM 의 박자에 맞춰 웹을 쏘면 고도를 유지하며 다음 건물로 넘어가고, 박자를 놓치면 고도가 꺼져 추락한다.
스테이지마다 서울의 실제 지역을 하나씩 가로지르고, 마지막에는 그 동네의 랜드마크 정상까지 타고 오른다.

## 실행

### 1. 웹에서 바로 — GitHub Pages

**https://rockyhong-a11y.github.io/DaDaDa/** — PC · 모바일 브라우저 모두 지원한다.

저장소 **Settings → Pages** 의 소스 설정에 따라 아래 셋 다 동작한다.

| Pages 소스 | 서빙되는 것 | 비고 |
|-----------|-----------|------|
| **Deploy from a branch → `/docs`** (권장) | `docs/index.html` | CI 불필요. 커밋된 단일 파일이 곧바로 루트 URL 이 된다. |
| Deploy from a branch → `/` (root) | 루트 `index.html` → `./docs/` | 한 번 넘어가므로 주소가 `/DaDaDa/docs/` 가 된다. |
| GitHub Actions | `dist/` | `.github/workflows/pages.yml` 의 push 트리거 주석을 풀어야 자동 배포된다. |

> 브랜치 배포와 Actions 배포가 **동시에** 켜져 있으면 push 마다 배포가 두 번 일어나
> 어느 쪽이 최종본인지 정해지지 않는다. 그래서 워크플로는 기본이 수동 실행이고,
> 브랜치 배포 하나만 자동으로 돌게 해 뒀다.

### 2. 그냥 열기 — 단일 HTML 파일

**`docs/index.html`** 을 브라우저로 열면 끝이다. 서버도 설치도 필요 없다.
JS·CSS·아이콘까지 전부 한 파일(약 1.1MB) 안에 들어 있어 USB 에 담아 다녀도 그대로 돌아간다.

### 3. 소스로 개발하기

```bash
npm install
npm run dev            # http://localhost:5173
npm run build          # dist/ + dist-single/dadada.html + docs/index.html
npm run build:single   # 단일 파일만
npm run build:pages    # 단일 파일 + docs/ 갱신
npm run preview        # 빌드 결과 확인
```

> **루트의 `index.html` 은 개발 서버용 진입점이다.** 브라우저로 직접 열면 실행되지 않는다
> (`file://` 에서는 origin 이 `null` 이라 모듈 스크립트·스타일시트가 CORS 로 차단된다).
> 직접 열면 흰 화면 대신 안내 문구가 뜨고, http(s) 로 서빙 중이라면 `./docs/` 로 자동 이동한다.
>
> 같은 이유로 `dist/index.html` 도 직접 열면 안 되고 정적 서버로 서빙해야 한다.
> 단일 파일 빌드는 번들을 IIFE 로 뽑아 일반 `<script>` 로 인라인하기 때문에 이 제약이 없다.

잠실에서는 35층 타워 사이를 지나 555m 정상까지 올라간다.

## 조작

| 입력 | 동작 |
|------|------|
| `Space` `J` `K` `F` `D` `↑` / **화면 아무 곳이나 탭** | 웹 발사 · 공중 트릭 |
| `Esc` | 일시정지 |

모바일은 세로·가로 모두 플레이할 수 있고, 가로가 시야가 넓다.
노치·홈 인디케이터 영역을 피해 HUD 를 배치했고, 주소창이 접히고 펴져도 캔버스가 따라 붙는다.

- **◆ 스윙 노트(청록 마름모)** — 새 웹을 쏴 다음 건물로 넘어간다.
- **● 에어 노트(분홍 원)** — 스윙 도중 넣는 공중 트릭. 점수와 모멘텀이 오른다.
- 판정은 `PERFECT / GREAT / GOOD / MISS`. 미스가 쌓이면 고도가 꺼지고,
  스윙을 연속으로 놓치거나 SWING POWER 가 0이 되면 추락해 실패한다.

싱크가 밀리면 **설정 → 오디오 오프셋**으로 보정한다.

## 서울 지도 데이터

### 좌표계

모든 지오메트리는 실제 위경도에서 출발한다. `src/world/geo.ts` 의 `GeoProjector` 가
스테이지 원점을 기준으로 위경도를 로컬 ENU 미터 좌표로 옮긴다
(`+X` 동, `+Y` 위, `−Z` 북). 도시 규모에서 등거리 원통 근사의 오차는 0.1% 미만이다.

### 스테이지 데이터 (`src/data/stages/`)

각 스테이지는 세 층으로 기술한다.

1. **경로(route)** — 실제 도로를 따라가는 위경도 웨이포인트.
   테헤란로는 방위각 69도로 강남역(37.4979, 127.0276)에서 삼성역(37.5088, 127.0631)까지 이어진다.
2. **랜드마크(landmarks)** — 실존 건물의 좌표·평면 크기·높이·층수.
   롯데월드타워 555m/123층, 파크원 타워1 333m/69층, 63스퀘어 250m/60층,
   트레이드타워 228m/54층, N서울타워 237m(해발 480m) 등. 높이는 공개된 실측값의 근사치다.
3. **블록(blocks)** — 도시 블록의 중심 좌표·크기·방위각과 용도(판상형 아파트, 타워형 아파트,
   고층 업무, 저층 상가, 재래시장, 공원, 수면 …). 생성기가 용도별 형태 규칙으로 건물을 채운다.
   목동 신시가지는 남향 판상형이 85~95m 간격으로, 테헤란로는 200×140m 블록이 도로 양쪽에 반복된다.

여기에 **지형(terrain)** 이 더해진다. 남산은 반경 900m·정상 243m 의 구릉으로 모델링되어
건물 지반고와 비행 고도에 실제로 영향을 준다 — 스테이지 5 후반은 산을 타고 오르는 구간이다.

경로 주변은 손으로 기술한 블록이, 그 바깥은 저주파 노이즈 기반 배경 시가지가 채워
지평선까지 빌딩숲이 이어진다. 스테이지당 약 7,500~10,500동이 생성되며 형태별 인스턴싱으로
드로우콜 몇 개에 처리된다.

### 실측 건물 데이터 (선택)

`npm run fetch:osm` 을 돌리면 OpenStreetMap Overpass API 에서 각 스테이지 영역의
**실제 건물 윤곽과 층수**를 받아, 폴리곤을 최소 면적 회전 사각형으로 근사해
`src/data/osm/*.json` 으로 굽는다. 데이터가 있으면 도시 생성기가 블록 규칙 대신 이 실측
발자국을 쓴다(`src/world/citygen.ts` 의 `placeOsmFootprints`). 랜드마크·지형·수면은 그대로 유지된다.

```bash
npm run fetch:osm            # 5개 스테이지 전부
npm run fetch:osm -- jamsil  # 특정 스테이지만
```

> 데이터를 굽지 않아도 게임은 그대로 돌아간다. 이 저장소에는 OSM 스냅샷을 커밋하지 않았다
> (라이선스 표기 부담과 용량 때문이며, 개발 환경의 네트워크 정책상 Overpass 접근이 막혀 있어
> 실제 응답으로 검증하지는 못했다). 사용 시 OpenStreetMap contributors / ODbL 1.0 표기가 필요하다.

### Google 실사 3D 타일 (선택 · 실험적)

**설정 → Google 3D Tiles API 키**에 본인 키를 넣고 "실사 3D 타일 배경 사용"을 켜면
Google Photorealistic 3D Tiles 를 게임 좌표계에 정합해 배경으로 띄운다
(`src/world/tiles3d.ts`). ECEF → 스테이지 원점 ENU → three.js Y-up 으로 변환한 행렬을
타일 그룹에 직접 물린다. 키는 브라우저 `localStorage` 에만 저장되고 어디로도 전송되지 않는다.

> 게임의 앵커·비행 고도는 자체 도시 모델에서 계산하므로 실사 타일과 완벽히 일치하지는 않는다.
> 배경 레이어로만 쓰는 실험 기능이며, 키가 없으면 모듈 자체가 로드되지 않는다.
> API 키가 없어 실제 타일 응답으로는 검증하지 못했다.

## 리듬 · 음악

BGM 은 **오디오 파일이 아니라 Web Audio 로 실시간 합성**한다(`src/audio/`).
덕분에 노트 차트와 음악이 같은 시계를 공유해 구조적으로 어긋날 수 없고, 저작권 문제도 없다.

- `conductor.ts` — 마스터 클럭. 모든 시간은 `AudioContext.currentTime` 기준이라
  프레임 드랍이나 탭 전환에도 판정이 밀리지 않는다.
- `voices.ts` — 킥·스네어·클랩·하이햇·베이스·리즈·플럭·패드·스탭·스윕을 절차적으로 합성.
- `music.ts` — 16분음표 단위 룩어헤드 시퀀서. 스타일 프리셋(시티팝 / 신스웨이브 / K-POP /
  드럼앤베이스 / 하드코어)마다 드럼 패턴·코드 진행·베이스 라인이 다르고, 16마디 주기로
  브레이크다운과 빌드업이 들어간다.
- `sfx.ts` — 판정음은 정확도에 따라 음정이 달라지고, PERFECT 콤보가 쌓이면 음이 올라간다.

노트 차트는 `src/game/chart.ts` 가 지형에서 생성한다.

```
리듬 패턴(박자 단위) → 스윙 구간 분할 → 앵커 옥상 선택 → 비행 고도 결정 → 건물 관통 회피
```

- 스윙 주기(기본 2박)마다 새 웹을 쏘고, 그 사이 노트는 공중 트릭(에어 노트)이 된다.
  덕분에 16비트 밀도를 유지하면서도 스윙 간격은 20~35m 로 자연스럽게 유지된다.
- 앵커는 목표 고도에 가장 어울리는 옥상을 고르고, 필요한 높이만큼 옥상 철탑을 세운다
  (실제 서울 옥상의 통신 철탑·광고탑처럼 보이도록 항공장애표시등을 얹었다).
- 궤적은 앵커를 중심으로 시작점과 끝점을 구면 보간한 진자 곡선이다. 줄 길이를 함께 보간해
  웹을 감았다 푸는 느낌을 낸다.
- 마지막으로 궤적을 샘플링해 건물을 뚫는 지점이 있으면 고도를 밀어 올린다.
  현재 5개 스테이지 전부 **관통 0**.

검증용 스크립트가 함께 있다.

```bash
./scripts/run-dev.sh src/dev/citycheck.ts    # 스테이지별 건물 수·높이 분포
./scripts/run-dev.sh src/dev/chartcheck.ts   # 노트 수·속도·고도·로프 길이·관통 검사
```

## 렌더링

- **three.js r185**, WebGL2. 후처리는 `UnrealBloomPass` + `OutputPass`(ACES 톤매핑).
- 건물은 형태별 `InstancedMesh` 로 묶고, 커스텀 GLSL 로 창문 격자를 절차적으로 그린다
  (`src/world/buildingShader.ts`). 용도마다 창 간격이 다르고, 켜진 창의 비율·밝기·색온도
  (백색·전구색·형광색)가 흩어지며, 저층부는 상가라 항상 밝다.
- 창문 격자는 **거리가 아니라 픽셀당 격자 수**(`fwidth`)로 디테일을 끈다. 원경에서 격자가
  지글거리지 않고 건물 전체가 은은하게 빛나는 덩어리로 자연스럽게 수렴한다.
- 90m 넘는 건물 옥상에는 항공장애표시등이 각자 다른 주기로 깜빡인다.
- 시간대 프리셋(노을 / 땅거미 / 밤 / 새벽)마다 하늘 그라디언트·태양 방향·안개·창문 점등률·
  블룸 세기가 통째로 바뀐다.
- 한강·석촌호수는 잔물결과 도시 불빛 반사를, 지면은 도로 격자와 가로등을 셰이더로 그린다.

## 모바일 대응

- **입력** — 화면 아무 곳이나 탭하면 웹이 나간다. 포인터 리스너를 캔버스가 아니라 `window`
  에 붙였다. HUD 오버레이가 화면 전체를 덮고 있어 캔버스에만 붙이면 터치가 닿지 않는다.
- **오디오** — 첫 제스처에서 `AudioContext` 를 깨우고 무음 버퍼를 한 번 흘려보내
  iOS Safari 의 오디오 잠금을 푼다.
- **화질** — 첫 실행 시 포인터 종류·코어 수·메모리·화면 크기로 화질을 정하고
  (`detectQuality`), 총 픽셀 수 예산을 둬 고DPR 폰에서 셰이딩이 폭주하지 않게 한다.
  플레이 중 프레임이 계속 모자라면 한 단계 자동으로 낮춘다(설정에서 직접 고르면 자동 조정 해제).
- **레이아웃** — `100dvh` 와 `env(safe-area-inset-*)` 로 주소창·노치를 피하고,
  세로 높이가 좁은 가로 모드에서는 HUD 를 압축한다. 캔버스 크기는 `window.innerHeight` 가
  아니라 캔버스의 실제 CSS 크기에서 읽는다.

## 단일 파일 빌드

`vite.single.config.ts` 의 `inlineEverything` 플러그인이 산출물을 HTML 하나로 합친다.

- `rollupOptions.output.format: 'iife'` + `inlineDynamicImports: true` — 코드 분할을 없애
  동적 import 까지 한 번들로 합친다. 모듈이 아닌 일반 스크립트라 `file://` 에서 CORS 에 걸리지 않는다.
- `assetsInlineLimit: MAX_SAFE_INTEGER`, `cssCodeSplit: false` — 에셋과 CSS 를 전부 인라인.
- 인라인할 때 `String.replace` 의 **치환 문자열 대신 함수**를 쓴다. 문자열을 쓰면 번들 코드
  안의 `$&` `$1` 같은 시퀀스를 replace 가 치환 패턴으로 해석해 JS 가 조용히 깨진다.
- 코드·CSS 안의 `</script` `</style` 는 이스케이프해 태그가 조기 종료되지 않게 한다.

## 개발용 URL 파라미터

| 파라미터 | 동작 |
|----------|------|
| `?stage=<id>` | 타이틀을 건너뛰고 바로 시작 (`mokdong` `yeouido` `jamsil` `teheran` `cbd`) |
| `?auto=1` | 자동 플레이 (데모·검증용) |
| `?debug=1` | FPS · 카메라 거리 · 고도 표시 |

예: `http://localhost:5173/?stage=jamsil&auto=1&debug=1`

## 설정

음악/효과음 볼륨, 오디오 오프셋(±150ms), 그래픽 품질(낮음은 블룸을 끄고 해상도를 제한),
Google 3D Tiles 키. 기록과 설정은 `localStorage` 에 저장되며, 저장이 막힌 환경에서도
게임은 그대로 돌아간다.
